### 立刻做（5 分鐘，止血）

**1. 先把東西送出去。** 現在最緊迫的不是任何程式問題，是 6 個 commit 只有一份副本、還放在會被 iCloud 亂動的 `.git/` 裡。二選一：

- `git push -u origin v3.1.5-cross-platform`（推薦，順便讓 CI 跑一次真正的乾淨 clone 情境）；或
- 至少重拍一次 bundle：兩個 repo 各跑 `git bundle create ~/fa-report-refactor-backups/<name>-$(date +%Y%m%d-%H%M).bundle --all`

> **補充（稽核後狀態更新）**：稽核期間 `gh` 仍是 `KennyKang7012`、兩個 repo `push=false`。肯尼大 已於稽核進行中完成 `gh auth login` 切換到 `kcf7012`，實測兩個 repo 皆為 `admin=true push=true`，且 token 帶 `workflow` scope。**push 這條路現在是通的，不需要再等權限。**

### 根治（15 分鐘，已實測可行）

**2. 把 venv 移出 iCloud，程式碼原地不動。** 這是「不搬家」前提下最好的解法 —— `chflags` 只是跟同步賽跑（實測 11 分鐘就輸一次），這招是直接退出比賽：

```bash
export UV_PROJECT_ENVIRONMENT="$HOME/.venvs/fa-report-improvement"
```

**scratchpad 實測過**：`uv sync` 會把 venv 建在指定的外部路徑，專案目錄下**完全不產生 `.venv`**。效果三重 ——（a）`.pth` 永遠不會被設 hidden，CLI 不再壞；（b）少掉 4,715 個 hidden 檔（venv 佔全部 hidden 的近半），iCloud 同步壓力大減；（c）不必再動 `chflags`。寫進 `~/.zshrc` 或專案的 `.envrc` 即可。

**但要講清楚它治不了什麼**：`.git/` 還是在同步範圍內，「iCloud 還原出前後不一致的 object/index/ref」這個最大風險**原封不動**。所以第 1 點的 push/備份還是得做。

**3. 真正的根治仍然是搬出 `~/Desktop`**（例如 `~/Projects/`）。第 2 點是緩兵之計，不是替代方案。
