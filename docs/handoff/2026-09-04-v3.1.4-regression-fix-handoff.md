## 3. 修正策略

### 3.1 為什麼用 `TITLE_SAFE_LEFT_INCH - 0.2` 不是 `TITLE_SAFE_LEFT_INCH`

對 10 in 標準寬度 slide(260811 用此寬度):
- `margin = TITLE_SAFE_LEFT_INCH = 1.2` → `content_w = sw - 2*margin = 7.6` ❌(測試 `>= 8.0` fail)
- `margin = TITLE_SAFE_LEFT_INCH - 0.2 = 1.0` → `content_w = sw - 2*margin = 8.0` ✅(測試 `>= 8.0` pass)

`1.0` 也與 `_safe_shape.safe_textbox` fallback 邏輯一致(`margin = TITLE_SAFE_LEFT_INCH - 0.2`)。

加 floor 保護:
```python
margin = TITLE_SAFE_LEFT_INCH - 0.2
if margin < 0.5:
    margin = 0.5
```

## 6. 重要規則和限制

### 6.1 rebase 衝突 markers 殘留問題(本次踩坑)

**踩坑過程**:
1. 開始分支 `v3.1.4-regression-fix`(基於 main HEAD `5cb68a4`)
2. 第一次 commit `eb9afe3` 只修 `basic_info.py`(當時以為是單檔問題)
3. 進一步檢查發現 8 檔需要修,撤回 `eb9afe3`(git reset --hard HEAD~1)
4. 第二次 commit `ad1e5d5`(基於 reset 後的狀態)— 但 reset 沒 push,remote 上還有 eb9afe3
5. 第二次 push 時 rebase,衝突 markers (`<<<<<<< HEAD` / `=======` / `>>>>>>> ad1e5d5`) **殘留在 `b071b00` merge commit**
6. CI Run #24 全 fail:`invalid-syntax: Expected ',', found name`(衝突 markers 是不合法 Python 語法)
7. 第三次 commit `6e4089b` 手動清除衝突 markers → CI 綠

**教訓**:
- 🚫 **永遠不要假設 rebase 自動解決衝突就沒事** — 必須 `git diff` 確認 markers 完全清乾淨
- 🚫 **reset --hard + force-push** 是危險的 — 任何 commit message 不精準都可能導致後續 rebase 出問題
- ✅ **建議未來流程**:reset 後,**先 git diff 確認無衝突 markers**,再 force-push
